## Why

Quintara 现有桌面版本已能串联部分后端能力，但首次启动、数据准备、训练和结果阅读仍暴露技术对象与原始 JSON，普通用户难以判断下一步，Linux/WSLg 的实际启动链路也未达到稳定产品标准。与此同时，产品所有者进一步确认：用户应在首次使用时主动选择 Quintara 供应方维护的比赛生产数据或自己的 CSV，所选数据落盘后在本机训练；这需要成为数据合同，而不是发布说明中的临时约定。

本轮把上述问题整合为一次产品体验与数据交付升级，并以真实桌面操作、跨平台安装和完整训练旅程作为发布门禁。依据 C-006、C-008、C-023、C-058、C-065–C-080、C-090、T01–T08、UI03–UI21，以及 2026-08-24 产品所有者对“供应方自带数据”的补充确认。

## What Changes

- **BREAKING**：发布版桌面呈现层从临时 Qt Widgets 页面迁移为 PySide6 Qt Quick/QML 单主窗口；保留 Python 应用服务、算法内核、CLI 和已发布存储身份。
- 首次启动以可恢复向导完成风险声明、环境检查和数据来源选择；主界面采用左侧导航、明确的下一步、通俗状态与按需展开的技术详情。
- 新增“Quintara 标准生产数据”来源：它代表比赛生产管线产出的、由供应方发布的版本化数据包，可随安装介质提供或联网下载，校验后保存在本地并用于本机训练。
- 保留用户 CSV 来源，继续执行严格可训练检查且不静默清洗；供应方数据、用户 CSV、PIT 基线、自定义股票池和非 PIT 回退保持可追溯身份隔离。
- BaoStock 成为已选本地数据的受控更新路径：在大规模传输前完成 PIT/许可/空间/兼容性预检，支持真实进度、取消、断点续传、校验与原子激活。
- 数据、股票池、训练、结果和历史改为任务导向页面；默认页面不展示原始 JSON。结果页优先展示五只研究组合、名称/代码/交易所、固定权重、模型评分、数据身份和风险提示。
- 修正默认策略为“稳健平衡”，明确激进/稳健/保守策略的可解释风险差异；技术配置放入高级区域。
- 建立可复用设计令牌、浅色/深色主题、中文排版、125%–200% DPI、小屏、键盘焦点和基础 Qt 可访问名称的验收基线。
- 建立 Quintara 基础品牌图标：以“可追溯研究罗盘 + 五档组合排序”为核心意象，提供无文字的源母版与 Windows 多尺寸 `.ico`，一致用于窗口、任务栏、可执行文件、开始菜单、桌面快捷方式和安装器。
- **BREAKING**：Windows 发布物拆分桌面 GUI 与控制台 CLI 启动身份；桌面快捷方式启动无控制台窗口的 GUI 子系统可执行文件，源码/wheel 通过 `quintara-gui` GUI script 进入同一 QML 入口，CLI 继续保留标准输入输出和退出码。
- 建立 Windows、原生 Linux 与 WSLg 的真实可见窗口启动、核心 GUI 旅程、安装/卸载、长任务和截图回归门禁；进程存活式 offscreen smoke 只作为快速检查。
- Linux 正式 one-file 发行物固定在 Ubuntu 22.04/glibc 2.35 或更旧 ABI builder 生成，并用可重复的 ABI 审计阻断把 Ubuntu 24 调试产物直接交付给 Debian 12/13。
- 候选标记由机器可读 gate 统一判断 OpenSpec 任务、原生矩阵、ABI、图标、法律材料、回滚和制品证据；不设置独立审阅或发行负责人签字字段，预发布阶段保留明确 blocker。

### Goals

- 新用户在首次启动后无需理解目录、manifest、PIT 缩写或 JSON，即可选定数据、完成本地准备并发起一次训练。
- 数据来源、版本、截止日、覆盖范围、体积、校验状态和本地位置始终可见且可追溯。
- 训练期间的状态、进度、停止、失败原因与恢复动作真实且一致，GUI 与 CLI 共用同一应用服务。
- 结果首先回答“本次模型输出了什么、依据哪份数据、风险边界是什么”，技术证据保留在详情中。
- 所有发布平台以接近普通用户的安装与操作旅程产出自动化证据。
- Windows 用户从桌面或开始菜单打开 Quintara 时只看到产品窗口；图标在 16、20、24、32、48、64、128 和 256 像素场景中仍可辨识。

### Non-goals

- 本轮不替换比赛生产算法内核，不改变 Quintara 产品标签和五只组合固定权重合同。
- 不引入浏览器界面、HTTP 服务、云账号、遥测、券商接入或自动交易。
- 不把用户 CSV 自动修复为可训练数据；检查报告只指出问题和定位。
- 不把 Figma 设为构建前置条件；设计令牌与组件可在仓库内独立演进。
- 不承诺完整 WCAG 认证；稳定版仍覆盖键盘焦点、状态辨识和基础辅助名称。

### Success gates

- 新建用户目录下，供应方数据与用户 CSV 两条路径均能完成“选择—预检—落盘—训练—Top-5 结果—CSV 导出”。
- 供应方数据包在损坏、签名/哈希不符、空间不足、断网、取消和应用退出时保留上一可用版本，不发布半成品。
- Windows 11、Ubuntu 22.04/24.04、Debian 12/13 和具备 WSLg 的 Windows 环境完成真实窗口启动；Windows 10 22H2继续按 best-effort 记录。
- 125%、150%、200% 缩放及浅色/深色主题的关键页面截图、文本截断和点击目标检查通过。
- Windows 安装器、桌面/开始菜单快捷方式和 GUI 可执行文件显示同一 Quintara 图标，双击 GUI 后不创建或常驻 PowerShell、Windows Terminal 或控制台宿主窗口；独立 CLI 入口的输出、退出码和管道行为保持通过。
- GUI 自动化断言用户可见结果和状态转换，而非仅断言控件存在或进程存活。

## Capabilities

### New Capabilities

- `first-run-data-choice`: 首次向导、风险确认、环境摘要、供应方生产数据/用户 CSV 的显式选择与可恢复状态。
- `provider-production-data`: 供应方比赛生产数据包的版本、清单、获取、校验、本地存储、BaoStock 更新和原子激活合同。
- `desktop-product-experience`: Qt Quick/QML 桌面信息架构、设计系统、页面状态、股票池工作区和基础交互质量。
- `long-running-operations`: 下载、检查、训练和预测任务的进度、停止、失败、恢复以及应用退出语义。
- `research-results-workspace`: 结果优先的 Top-5 组合、解释、溯源、历史与 CSV 导出体验。
- `desktop-release-evidence`: Windows/Linux/WSLg 启动、安装、真实 GUI 旅程、视觉回归和发布证据门禁。

### Modified Capabilities

当前基线规范尚未归档到 `openspec/specs/`；本变更以新能力表达 v2 合同，并在归档时与 `quintara-stable-v1` 对应能力合并。

## Impact

- **桌面层**：`src/quintara/gui` 的 Widgets 视图、导航、状态绑定和启动适配将在实施阶段由 QML 呈现层替代；Python 服务接口保持唯一业务入口。
- **数据层**：增加供应方发布清单、版本化数据包、下载缓存和本地 generation；既有 BaoStock、PIT、CSV 校验与身份门禁需要接入统一来源模型。
- **任务层**：下载、校验、训练、预测统一进入可观察任务状态机；现有同步调用和临时日志展示需要迁移。
- **打包层**：PyInstaller/安装器增加 QML 资源、Qt 插件预检、Linux/WSLg 平台适配、品牌图标、Windows GUI/CLI 双入口，以及可选内置数据或远程数据目录配置。当前单一 `console=True` 可执行文件不再作为桌面快捷方式目标。
- **质量层**：测试从控件/进程 smoke 扩展为用户旅程、截图、DPI、键盘、取消恢复和数据故障注入；发布说明必须链接可核验的 CI 证据。
- **兼容性**：CLI 命令与旧数据保持读取兼容；发布 GUI 的布局和入口发生有意变化。旧 generation 仅在清单身份完整且通过迁移检查后复用。
