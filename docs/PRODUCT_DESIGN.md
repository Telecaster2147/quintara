状态：历史总体设计草案；交互、标签和稳定版范围已由
[`openspec/openspec/changes/quintara-stable-v1/`](openspec/openspec/changes/quintara-stable-v1/)
覆盖。本文保留早期分析背景，实施以 OpenSpec 为准。  
产品名：**Quintara**  
产品源内核：`/home/olm/bigdata/bigdata/app`  
目标平台：Windows 10/11 x86-64、主流 Linux x86-64

## 1. 产品定位

Quintara 将现有比赛生产代码包装为可安装、可诊断、可更新数据、可训练和可生成结果的
本地开源软件。用户使用软件自带的历史 BaoStock 数据，或者导入通过可训练性检查的 CSV，
训练既有 LightGBM 横截面排序模型，并得到下一周候选的五只股票组合。

Quintara 的第一原则是**包装生产内核，而不是另起一套算法**：标签、PIT 股票池、特征、
模型配置、训练、预测和组合输出均以 `bigdata/app` 当前生产路径为准。

首版范围：

- 本地单用户应用；
- 开源发布于 GitHub；
- 一个共享核心引擎；
- 普通 shell CLI；
- 独立中文桌面 GUI；
- 自带数据与用户 CSV 两种数据源；
- 基础行情的一键增量更新；
- 环境探测、训练、预测、审计报告和运行历史；
- CPU 为兼容基线，GPU 为可选加速能力。

首版不包含：

- TUI；
- 云端账户系统；
- 券商账户接入和自动交易；
- 多租户服务；
- BaoStock 扩展特征进入模型；
- 与当前生产代码不同的模型或标签；
- 收益承诺。

## 2. 当前内核基础

现有 `bigdata/app` 已具备：

- 历史沪深 300 PIT 成分门禁；
- 上市状态与关键 OHLC 合法性检查；
- 原比赛差分 fixture 使用 `open(T+5) / open(T+1) - 1`；产品默认标签使用
  `close(T+5) / open(T+1) - 1`；
- LightGBM 横截面排序训练；
- 固定随机种子、轮数和线程；
- 最多五只股票及固定排名权重输出；
- 输入、源码、配置和模型工件哈希；
- pending/current generation；
- 结果事务发布与中断恢复；
- 确定性 CPU 默认路径及可选 OpenCL GPU 路径。

因此，产品化工作的核心是跨平台适配、数据生命周期、交互、安装、诊断和测试。

## 3. 总体架构

```text
CLI ───────────────┐
                   ├─ Application Service / Job Orchestrator
Desktop GUI ──────┘              │
                                  ├─ Environment Doctor
                                  ├─ Dataset Registry
                                  ├─ CSV Trainability Validator
                                  ├─ BaoStock Updater
                                  ├─ Production Kernel Adapter
                                  ├─ Run / Artifact Registry
                                  └─ Report Generator
                                                │
                           bigdata/app production kernel
```

### 3.1 共享核心引擎

CLI 和桌面 GUI 只负责输入输出，不各自实现训练逻辑。共享引擎负责：

- 配置解析；
- 数据集选择与版本管理；
- 环境检查；
- 数据更新与导入；
- 调用生产训练、推理和组合构造；
- 任务锁、进度、取消和失败恢复；
- manifest、日志、报告和结果归档。

### 3.2 生产内核适配层

适配层是 Quintara 与 `bigdata/app` 的唯一连接点。它以进程内 Python API 或受控子进程
调用内核，并将生产日志、进度和工件转换成统一任务事件。适配层不得复制 `data.py`、
`model.py`、`train.py`、`predict.py` 中的经济逻辑。

## 4. 用户交互

### 4.1 CLI

CLI 使用普通命令和文本输出，不引入全屏交互：

| 命令族 | 作用 |
|---|---|
| `quintara doctor` | 检查系统、硬件、依赖、数据和联网条件 |
| `quintara data list` | 列出自带、活动和用户数据集 |
| `quintara data validate PATH` | 生成 CSV 可训练性报告 |
| `quintara data import PATH` | 导入已通过检查的数据集 |
| `quintara data update` | 更新软件自带基础行情至最新可用日期 |
| `quintara train` | 使用所选数据和年限训练生产内核 |
| `quintara predict` | 从当前 generation 生成五股结果 |
| `quintara run` | 串联检查、可选更新、训练和预测 |
| `quintara runs` | 查看历史运行、数据和模型版本 |
| `quintara report` | 导出运行与结果报告 |

CLI 同时提供稳定的 `--json` 输出；日志和 JSON 中隐藏凭据。写操作使用明确动词，并支持
适用场景下的 `--dry-run` 或预览。

### 4.2 独立桌面 GUI（最新规范见 OpenSpec）

首个稳定版使用 PySide6/Qt Widgets 独立桌面 GUI，不启动 HTTP 服务或浏览器。页面包括：

1. 首次启动向导；
2. 环境诊断；
3. 数据集中心；
4. BaoStock 更新；
5. CSV 导入与检查报告；
6. 训练配置与任务进度；
7. 五股结果和方法说明；
8. 历史运行、数据版本和模型 generation；
9. 日志及诊断包导出。

桌面 GUI 和 CLI 具有相同能力边界，调用相同应用服务。

## 5. 安装和发布

### 5.1 Windows

- Windows 10/11 x86-64；
- 提供 MSI 或签名安装程序；
- 携带应用所需 Python 运行时、锁定依赖和启动器；
- 创建开始菜单入口，并将 CLI 可选加入用户 PATH；
- CPU 版作为默认包；
- GPU 支持作为显式可选组件；
- 提供标准卸载入口。

### 5.2 Linux

- 优先提供 AppImage 与 `.deb`；
- 后续按用户需求补 `.rpm`；
- CPU 包作为兼容基线；
- GPU 运行时由环境探测后启用；
- CLI 安装到用户级路径或系统 PATH。

### 5.3 构建策略

- Windows 包在原生 Windows CI runner 构建和测试；
- Linux 包在目标发行版矩阵或容器中构建；
- 不跨平台复制 `.venv`；
- `uv.lock` 作为 Python 依赖闭包来源；
- 应用包与大体积数据包分开版本化；
- 发布产物生成 SHA256 和 SBOM；
- GitHub Releases 承载版本化二进制和校验文件。

Briefcase 可作为 MSI、AppImage、deb/rpm 的候选打包器；进入实现阶段后再用最小
LightGBM 原型比较 Briefcase、PyInstaller 加平台安装器两条路线。

## 6. 数据生命周期

### 6.1 数据分层

```text
bundled/   安装包附带、只读的基线版本
active/    当前训练选中的已发布版本
staging/   更新或导入过程中的临时版本
archive/   历史版本和回退点
```

数据版本独立于程序版本。每个数据版本包含：

- 基础行情；
- PIT 成分区间；
- 上市状态；
- input manifest；
- 文件哈希；
- 日期、股票和行数统计；
- 数据来源及生成时间；
- 检查报告。

### 6.2 一键 BaoStock 更新

`data update` 或桌面 GUI 的“更新数据”执行一个完整事务：

1. 获取独占更新锁；
2. 运行网络、磁盘和 BaoStock 登录探针；
3. 读取活动数据的最大交易日期；
4. 计算需要拉取的日期和股票代码；
5. 拉取基础日行情与生产所需元数据；
6. 保存到 staging，并记录断点进度；
7. 按 `(股票代码, 日期)` 精确 replacement/union；
8. 运行 schema、主键、覆盖率、日期和 PIT 检查；
9. 检查更新前后键级行数守恒；
10. 生成 manifest 和 SHA256；
11. 原子发布新的 active 版本；
12. 保留上一版本和更新报告。

网络失败采用有界重试；在本开发环境中，联网故障排查先执行 `unsetproxy` 再重试。

现有 `bigdata/tools/fetch_baostock_increment.py` 作为抓取实现参考，但进入 Quintara 前需
拆分为下载、校验、合并和发布四个清晰阶段。

### 6.3 扩展特征策略

首版只更新和使用当前生产内核实际依赖的基础数据。BaoStock 估值、行业、财务、预测报告
等扩展特征暂不进入 Quintara 数据更新闭包，也不进入训练。

未来启用任一扩展特征时，应先满足：

- 生产内核已正式使用；
- 有完整字段契约；
- 财务/公告类数据按真实发布日期 as-of；
- 当前快照不回填历史；
- 无 future/label leakage；
- 通过预注册 walk-forward 和单独消融；
- 数据源、模型配置和 manifest 同步升级。

## 7. 用户 CSV 可训练性检查

Quintara 负责检查和报告，不对用户 CSV 做隐式清洗。检查至少包括：

- 编码、分隔符和表头；
- 必需列、列类型和单位；
- 股票代码、日期规范；
- `(股票代码, 日期)` 重复键；
- 每股日期单调性；
- OHLC 有限正数及高低价关系；
- NaN、Infinity、异常零值；
- 用户选择的 `x` 年是否有足够历史；
- 单股滚动窗口和标签所需交易日；
- 交易日、股票和横截面覆盖率；
- PIT 成分和上市状态资料；
- 预计内存、磁盘与训练时间。

报告分为 `PASS`、`WARNING`、`FAIL`，包含字段、具体行号、影响范围、可训练区间和用户需
自行处理的事项。只有 `PASS` 数据集可设为 active。

若用户只提供行情而缺少 PIT 成分/上市状态，应明确标记数据契约不完整；严谨生产模式
要求行情、历史成分和上市状态形成同一个可审计版本。

## 8. 环境探测

首次启动和每次训练前运行 doctor：

- OS、版本、架构和是否处于 WSL；
- CPU 型号、逻辑/物理核心数；
- 内存、可用磁盘和文件系统；
- NVIDIA GPU、显存、驱动；
- CUDA/OpenCL 运行时及 LightGBM 最小探针；
- Python、Quintara 和锁定依赖版本；
- 数据目录读写、锁和原子 replace 能力；
- BaoStock DNS、连接和登录状态；
- 活动数据、模型 generation 和哈希；
- 根据数据规模估算的训练资源。

CPU 是结果兼容基线。GPU 只有在探针和兼容矩阵通过后才由用户显式选择，并在运行报告中
记录设备、驱动和模型工件身份。

## 9. 训练和结果流程

```text
环境检查
  → 选择 bundled/active/user 数据集
  → 可选更新或 CSV 检查
  → 选择过去 x 年（满足最小训练窗口）
  → 生产 PIT 门禁与特征工程
  → 生产 LightGBM 训练
  → generation + manifest
  → 生产推理
  → 五股 result.csv
  → 用户报告与运行归档
```

输出包括：

- `result.csv`；
- 五只股票及权重；
- 数据截止日；
- 数据、配置、源码和模型 generation；
- 训练耗时与设备；
- 输入检查摘要；
- 方法、限制和风险说明。

## 10. 激进、稳健、保守策略

稳定 v1 提供三个有界策略预设。它们只调整训练阶段的模型容量、采样比例和时间衰减，
不改变候选排序后的固定组合契约；因此策略身份会进入配置 hash，结果仍严格使用五只和
`[0.40, 0.25, 0.15, 0.12, 0.08]`。更复杂的风险约束组合构造仍属于后续独立验证范围。

候选实现：从模型排名靠前的候选池中，根据预测分数、波动、下行风险、股票相关性、
流动性、行业集中和交易成本构造最多五只股票。

| 档位 | 稳定版作用 |
|---|---|
| 激进 | 更高模型容量与特征/样本采样比例，追求排序灵活度 |
| 稳健 | 中等容量与采样比例，作为默认平衡档 |
| 保守 | 更低容量、采样比例与更长时间衰减，减少近期噪声 |

必须通过按时间 walk-forward 验证，并报告：

- 含 20bp/50bp 成本的收益；
- 波动与下行风险；
- worst/negative windows；
- turnover；
- 组合集中度；
- 与当前固定权重生产基线的差异。

稳定版保持当前生产排名权重 `[0.40, 0.25, 0.15, 0.12, 0.08]`，避免包装阶段同时
改变算法结论。完整波动/成本 walk-forward 评估作为后续策略升级门禁。

## 11. 开源定位与合规边界

Quintara 当前定位为 GitHub 上的免费、本地、研究型开源软件，不接券商账户，不执行交易，
不承诺收益，也不提供收费投顾服务。因此，证券业务资质不作为首版开源开发的交付门槛。

但“免费开源”本身不会改变软件具有具体股票选择功能这一事实。README 和界面应如实说明：

- 研究和技术演示定位；
- 数据来源；
- 模型方法与局限；
- 输出不构成收益保证；
- 用户自行评估和承担决策结果。

若未来出现收费、个性化咨询、托管服务、公开运营荐股、券商/交易接口或机构合作，再启动
正式法律与数据授权评审。证监会对“预测具体证券走势、提供具体品种选择建议”的软件有
专门定义和监管文件：

- <https://www.csrc.gov.cn/csrc/c101838/c1021995/content.shtml>
- <https://www.csrc.gov.cn/csrc/c101950/c1048010/1048010/files/%E9%99%84%E4%BB%B61%EF%BC%9A%E3%80%8A%E5%85%B3%E4%BA%8E%E4%BF%AE%E6%94%B9%E9%83%A8%E5%88%86%E8%AF%81%E5%88%B8%E6%9C%9F%E8%B4%84%E8%8C%83%E6%80%A7%E6%96%87%E4%BB%B6%E7%9A%84%E5%86%B3%E5%AE%9A%E3%80%8B.pdf>

这部分在首版中表现为准确的项目说明，而不是扩张成账户、合同或投顾业务系统。

## 12. 测试与质量门禁

- 单元测试：配置、校验器、数据版本和任务状态；
- 性质测试：代码/日期归一化幂等、键级合并不变量、权重与输出不变量；
- 差分测试：Quintara 适配层结果与原生产入口一致；
- 故障注入：下载中断、磁盘不足、锁冲突、发布中断；
- E2E：CLI 与桌面 GUI 完整流程；
- 平台矩阵：Windows 10/11、Ubuntu LTS；
- CPU 结果复现；
- GPU 探针和兼容性测试；
- 依赖、静态扫描和供应链审计；
- 安装、升级、卸载和保留用户数据测试。
