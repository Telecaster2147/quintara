## 3. 第一轮问答

### A. 产品目标与用户

#### G01. 第一目标用户

Quintara 的第一目标用户是谁？是你自己、比赛选手、量化初学者、Python 开发者，还是
普通股票用户？只能选一个首要用户。

**回答：普通股票用户，他们可以没有任何的量化知识，如果需要学的话我们的文档可以告诉他们基本原理。**

#### G02. 核心价值

用户为什么要用 Quintara，而不是直接运行原来的 `train.sh/test.sh`？最核心的三个价值
是什么？

**回答：一键运行，实用化（原先的traintest太偏向于比赛评分了），可以自己补充数据**

#### G03. 主定位

你希望它更像哪类产品？请确定一个主定位：

1. 可复现的量化研究工具；
2. 一键选股工具；
3. 大数据竞赛成果展示；
4. 可扩展量化平台。

**回答：首先2，其次4**

#### G04. 第一版成功标准

第一版成功的衡量标准是什么？例如新用户十分钟内得到结果、Windows 零配置安装、与原

**回答：一键完成更新/训练/预测、Windows 零配置安装、整个流程可用而完整**

#### G05. 用户知识门槛

是否允许用户在没有金融和 Python 知识的情况下使用？如果允许，错误信息和结果解释需要

### 4.2 G24：缺失值边界解释

“软件不替用户清洗数据”指 Quintara 不悄悄修改用户原始 CSV，也不擅自猜测错误值。
但当前生产内核本身区分两类字段：

- **关键字段**：开盘、收盘、最高、最低等。缺失、非有限或非正值会让相应记录/日期失去
  训练资格；完整 300 股门禁也可能因此失败。
- **非关键字段**：成交量、成交额、换手率、涨跌幅等。生产内核允许部分缺失，通过缺失
  指示器和冻结的数值策略送入模型。

建议规则：导入检查忠实报告缺失情况；关键字段问题导致 `FAIL`；处于生产容忍范围内的
非关键缺失记为 `WARNING`，原始 CSV 保持不变，由生产内核按既有规则处理。

### 4.3 G44：LightGBM 与 Quintara 许可证

LightGBM 使用 MIT 许可证。MIT 允许使用、修改和分发，也允许 Quintara 选择 MIT 等兼容
许可证；核心要求是随分发副本保留 LightGBM 的版权和许可声明。引用 LightGBM 并不要求
Quintara 必须采用相同许可证。

当前建议：**Quintara 采用 MIT，并在 `THIRD_PARTY_NOTICES` 中保留 LightGBM 及所有打包
依赖的许可证文本。** 最终发布前还要对 Python、WebUI、安装器的完整依赖闭包做许可证
扫描，而不只检查 LightGBM。

依据：

- LightGBM 官方许可证：[https://github.com/lightgbm-org/LightGBM/blob/main/LICENSE](https://github.com/lightgbm-org/LightGBM/blob/main/LICENSE)
- LightGBM Python 包元数据：[https://github.com/lightgbm-org/LightGBM/blob/main/python-package/pyproject.toml](https://github.com/lightgbm-org/LightGBM/blob/main/python-package/pyproject.toml)

### 4.4 G45：什么是数据再分发

“再分发”是指开发者从 BaoStock 下载行情后，把下载得到的 CSV/数据库重新上传到
Quintara 安装包、GitHub Release 或其他公开地址，让第三方直接取得副本。

这与“每个用户在自己的电脑上运行 Quintara，由用户直接连接 BaoStock 并下载到本地”是
两种发布方式。BaoStock Python 客户端在 PyPI 标注为 BSD License，但**客户端代码许可
和服务端返回数据的公开分发条件是两件事**。BaoStock 官网免责声明对网站内容复制传播有
限制，而当前公开页面没有给出足以覆盖历史行情数据包公开再分发的清晰授权。

由于 G26 已选择“首次启动下载”，建议首版采用：程序仓库和安装器不附带行情数据；用户
首次启动时直接从 BaoStock 获取并保存在自己的电脑上。若以后希望在 GitHub Release
提供预制数据包，再向 BaoStock 取得明确许可或找到条款依据。

依据：

- BaoStock Python 包：[https://pypi.org/project/baostock/](https://pypi.org/project/baostock/)
- BaoStock 官网免责声明：[https://baostock.com/disclaimer](https://baostock.com/disclaimer)

### 4.5 G46：什么是遥测

遥测是软件把运行情况自动发送给开发者，例如：应用版本、操作系统、崩溃堆栈、功能使用
次数、耗时或硬件信息。即使不含姓名，这仍是从用户电脑向外传输数据。

建议 Quintara 首版**不上传遥测**。所有诊断、日志和硬件信息只保存在本机；用户遇到问题
时，可以主动导出经过脱敏的诊断包并自行附到 GitHub Issue。

## 11. UI 方向变更：独立桌面 GUI

### 11.1 当前决策

可以使用独立桌面 GUI，而且它比“启动本地服务再打开浏览器”的 WebUI 更符合 Quintara 面向
普通股票用户、Windows 零配置安装和桌面产品化的定位。

本次方向变更暂定如下：

| ID    | 状态      | 来源         | 需求                                                                                |
| ----- | --------- | ------------ | ----------------------------------------------------------------------------------- |
| C-060 | CONFIRMED | 用户最新指令 | 首个稳定版的主要交互入口由浏览器 WebUI 变更为独立桌面 GUI；正常使用时不启动浏览器。 |
| C-061 | CONFIRMED | 用户最新指令 | GUI 必须与 Windows 安装器、开始菜单和桌面快捷方式集成，表现为普通桌面应用。         |
| C-062 | CONFIRMED | 既有需求     | GUI 继续采用中文、简洁向导式设计，并保留首页、高级详情、首次向导和任务进度。        |

该变更覆盖 C-005、C-016、C-043、C-039、T26、T27 中关于 WebUI 的部分；这些条目保留
作为决策历史，其中“WebUI”在后续验收中统一解释为“桌面 GUI”；CLI 的最终范围以 C-064
和第五轮问答为准。

### 11.2 技术建议（由 Agent 负责）

首选 **PySide6 + Qt Widgets**：它与现有 Python/LightGBM 内核衔接直接，可打包为 Windows
独立程序，也支持 Debian/Ubuntu；不依赖浏览器、Node.js 或用户预装 Python。界面与训练
进程隔离，训练、更新、停止和清理通过后台任务进程执行，GUI 只负责交互和状态展示，避免
长训练卡死界面。

暂不选 Electron（安装体积和内存开销较大），也暂不选 Tauri（Linux WebKit 运行依赖和
Python 后端打包链更复杂）。发布前仍会核验 Qt/PySide6 的许可证义务，并写入
`THIRD_PARTY_NOTICES`。

## 14. 第五轮：CLI、股票范围与法律边界

GUI 方向已经闭合。本轮只补齐因“无桌面 Linux 也要稳定使用”和“法律部分做好”新增的产品语义。

### F01. 稳定版 CLI 功能范围

建议稳定版 CLI 覆盖：环境诊断、首次数据下载、数据更新、股票池查看/创建/导入/切换、CSV
检查与导入、训练、预测、一键运行、结果查看/导出、历史查看、任务停止、诊断包导出和版本
检查。是否接受这套完整范围？

**回答：接受**

### F02. CLI 交互方式

沿用 G37，默认使用普通的逐步问答式 shell；同时保留直接执行的子命令和明确退出码，方便
无桌面服务器和自动化测试。输出默认中文，日志可切换详细模式。是否接受？

**回答：可以**

### F03. 终端断开时的任务

CLI 训练期间关闭终端或 SSH 断开时，建议任务收到结束信号后停止、清理未发布工件并保留
日志；若用户希望长期运行，应自行使用 systemd/tmux 等系统工具。是否接受？

**回答：当然**

### F04. “A 股”资产边界

自定义股票池首版是否只支持上海、深圳、北京交易所的人民币普通股，并包含主板、科创板、
创业板和北交所股票；ETF、LOF、可转债、B 股、港股、美股、指数本身和基金暂不进入模型？

**回答：就A股，别的先别弄**

### F05. ST、退市整理与长期停牌股票

这些证券波动和可交易性特殊。建议默认允许进入数据仓库，但在股票池添加时醒目标记；训练和
预测仍按数据完整性规则过滤，结果页披露状态。是否还要提供一个默认开启的“排除特殊状态
股票”选项？

**回答：好**

### F06. 自定义池股票下限的计算时点

“至少 100 只”按用户清单数量计算，还是按每个训练截面的有效股票数计算？建议两层都检查：
清单少于 100 直接阻止；任一历史截面有效股票少于 100 时排除该日期。

**回答：好**

### F07. 推荐结果少于五只

若最新截面因停牌、缺失或状态过滤后剩余股票很多但合格候选少于五只，建议本次预测失败并
说明具体原因，不用低质量候选凑满五只。是否接受？

**回答：好**

### F08. 法律适用地区

Quintara 首版是否明确面向中国大陆公开市场数据和研究场景，中文免责声明据此编写；其他地区
用户需自行确认当地要求？

**回答：对待**

### F09. 风险声明确认方式

建议首次启动必须主动勾选并点击确认，记录“声明版本、确认时间、应用版本”到本机；声明更新
后重新确认。每份 CSV 结果同时写入简短风险提示和声明版本。是否接受？

**回答：好**

### F10. 结果页措辞边界

除“不保证收益、不构成投资建议”外，结果页是否统一使用“模型评分、研究组合、历史统计”，
避免“买入、卖出、目标价、稳赚、最佳投资”等行动性或保证性表述？

**回答：当然**

### F11. PIT 数据源失败时的降级

默认基线依赖历史成分区间。若首选 PIT 来源暂时故障，建议继续使用上一个经过校验且带截止日
的数据版本；不把当前静态沪深 300 冒充历史 PIT，也不发布来源不明的新版本。是否接受？

**回答：PIT如果失败的话可以让用户回退到无pit的训练，但是要警告**

### F12. 外部数据来源展示

数据页面和结果 manifest 是否必须展示每类数据的来源、获取时间、覆盖日期、校验状态、许可/
条款链接和内容哈希，使 BaoStock 行情与 PIT 成分数据可以独立追溯？

**回答：可以**

### 15.2 非 PIT 回退的产品规则

F11 允许用户主动降级，因此固定以下防误用门禁：

1. 先展示最后一个已验证 PIT 数据版本及其截止日，优先建议继续使用它。
2. 进入非 PIT 模式必须由用户主动选择并确认警告，应用不自动降级。
3. 非 PIT 模式使用当次静态股票池回看历史，明确提示幸存者偏差。
4. GUI 首页、CLI、CSV、manifest、运行历史和诊断包都显示 `NON_PIT_FALLBACK`。
5. PIT、非 PIT、自定义股票池分别生成独立的数据 generation、模型目录和结果记录。
6. PIT 数据恢复后提示用户切回并重新训练，不用非 PIT 模型直接产生 PIT 结果。

### 15.3 访谈闭合判定

截至第五轮，已不存在阻塞总体设计和实现的产品所有者问题。后续发现的普通实现细节由 Agent
按“稳定、可测试、桌面优先、数据与模型可追溯、默认不静默降级”的原则决策，并记录到架构
决策文档；只有出现会改变产品范围、金融语义或用户数据处理方式的新冲突时，才重新开启需求
拷问。

- 评估并实测可持续获取的沪深300历史 PIT 成分来源及许可条款；
- 核验 BaoStock 数据获取、缓存和发布方式的条款边界；
- 完成 PySide6、LightGBM、安装器及完整依赖闭包的许可证清单；
