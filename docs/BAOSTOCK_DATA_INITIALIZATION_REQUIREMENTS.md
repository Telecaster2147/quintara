# BaoStock 数据初始化与更新需求

## 1. 目标

Quintara 需要把“数据来源”和“当前活动数据”明确区分：

- **数据来源**：安装包自带开发者数据、从 BaoStock 初始化、用户自己的 CSV。
- **活动数据**：当前经过校验并被 Quintara 选中用于股票池、训练和结果生成的数据版本。

用户首次使用时不应被要求必须上传 CSV。首次向导应提供三个互斥选项：

1. 使用安装包自带开发者数据；
2. 从 BaoStock 初始化数据；
3. 使用自己的 CSV。

## 2. 首次从 BaoStock 初始化

用户选择“从 BaoStock 初始化”后，应用应提供清晰的分步流程：

1. 显示数据来源、预计股票数量、日期范围、预计下载量、目标工作目录和磁盘需求；
2. 连接 BaoStock 并获取证券主数据；
3. 获取或建立所选研究路线需要的股票池与历史成员材料；
4. 下载行情及受支持的额外字段；
5. 校验证券代码、日期、重复键、OHLC、数值范围、股票池覆盖和截止日期；
6. 在暂存目录完成全部检查后发布新的活动 generation；
7. 在数据页显示版本、来源、日期范围、截止日期、股票数量、占用空间和完整本地路径。

下载期间需要显示真实阶段、完成数量、失败原因和重试操作。上一份活动数据始终保持可用。

## 3. 已有活动数据的一键更新

活动数据建立后，数据页应提供“一键更新至最新交易日”。点击前显示：

- 当前来源与版本；
- 当前截止日期；
- 计划更新到的交易日；
- 预计更新的证券数量；
- 股票池或历史成员变化；
- 预计下载量和工作目录；
- 更新后的数据身份变化。

用户确认后，应用应从当前数据截止日的下一个有效交易日开始请求数据，更新到 BaoStock
实际可提供的最新完整交易日，而不是仅依赖操作系统当天日期。

更新采用“增量合并、完整校验、发布新 generation、原子切换”的方式。旧 generation
保持只读并可用于回滚，不直接覆盖原 CSV 或安装包数据。

## 4. 不同来源的更新规则

### 4.1 安装包自带开发者数据

- 原始压缩包继续保留在应用安装目录旁，不修改、不覆盖，也不移动到 AppData；
- 更新结果发布为新的“BaoStock 派生版本”，不得继续冒充固定的开发者参考版本；
- 固定参考版本仍执行包内参考结果一致性校验；派生版本展示自己的数据、模型和结果身份；
- 更新前核对历史数据与 BaoStock 新数据的复权口径、字段定义和单位；口径不一致时停止发布并说明差异；
- 更新历史 PIT 股票池时，需要续接新的成员区间，保留旧区间，处理成分加入、移出、代码变化和退市证券；
- 不应因为历史成员中存在当前已退市证券而阻断全部新增行情更新。

### 4.2 用户 CSV

- 源 CSV 保持原样；
- 默认按照当前活动股票池从 BaoStock 获取后续数据；
- 更新前展示 CSV 字段与 BaoStock 字段的映射、单位和复权口径；
- 新 generation 保存源 CSV 哈希、BaoStock 更新区间和合并报告；
- 用户可选择保持原股票池，或在明确确认后更新股票池定义。

### 4.3 BaoStock 初始化数据

- 后续更新沿用初始化时选定的研究路线、股票池和字段合同；
- 更新完成后展示新增交易日、增加行数、证券变化、字段变化和最新截止日期。

## 5. PIT 与股票池要求

- `PIT_BASELINE` 更新必须拥有可验证的历史成员区间，并将新区间正确续接到最新数据；
- 当前成分快照不得被静默当作完整历史 PIT 数据；
- 历史成员中的退市或代码变更证券应保留其历史记录；
- 自定义股票池更新应严格使用用户当前选择的代码集合；
- 研究路线或股票池发生变化时，模型和旧结果应标记为过期，但旧产物继续可复查。

## 6. GUI 与路径显示

- 首次向导明确显示三个数据来源，不使用“活动数据”指代来源；
- 没有活动数据时，数据页提供“导入自带数据”“从 BaoStock 初始化”“选择 CSV”三个操作；
- 已有活动数据时，主操作为“一键更新至最新交易日”；
- 更新过程中显示连接、证券主数据、股票池、行情、额外字段、校验、发布等阶段；
- 当前工作目录、安装包数据、活动 generation、最近 CSV 和最近导出路径持续可见；
- 修改工作目录后，所有相关页面立即显示新路径并跨启动保留。

## 7. 失败与恢复

以下情况不得发布半成品：

- BaoStock 登录或查询失败；
- 数据字段、单位或复权口径不兼容；
- PIT 成员区间不完整或发生重叠；
- 关键行情缺失、重复或 OHLC 校验失败；
- 磁盘空间不足；
- 用户取消；
- 应用退出或进程中断。

失败后应保留上一活动 generation，并展示失败阶段、影响范围、已下载进度和可执行的继续、
重试或重新规划操作。断点内容必须绑定请求范围和远端对象身份。

## 8. 验收标准

1. 新用户在没有 CSV 的情况下，可以仅通过 GUI 从 BaoStock 建立第一份可训练活动数据；
2. 新用户也可以直接使用安装包自带数据完成离线初始化；
3. 三种来源初始化后都能在数据页点击一次，将数据更新到 BaoStock 的最新完整交易日；
4. 更新从下一个有效交易日开始，不重复扩大历史区间；
5. 开发者参考版更新后形成独立派生身份，原始参考包和参考结果保持不变；
6. PIT 路线正确续接成员区间，退市历史证券不阻断整体更新；
7. 更新失败、取消或退出时，上一活动数据仍可训练和查看；
8. 更新成功后，新旧版本差异、截止日期、来源、股票池变化和完整路径均在 GUI 可见；
9. Ubuntu 本机完成三种来源的初始化与增量更新测试；Windows 通过 GitHub Actions 验证相同 GUI 流程；
10. 本需求同步写入当前 OpenSpec 的首次数据选择、数据提供方、长任务和发布旅程规范，并补充对应自动化证据。

## 9. 当前实现提示

现有代码已经具备 BaoStock 连接、行情查询、暂存检查点、旧数据合并、新 generation 发布和
GUI 后台任务入口，可作为实现基础。实施时重点补齐：首次 BaoStock 初始化入口、最新完整
交易日探测、开发者数据派生身份、复权口径检查、PIT 成员续接、退市证券处理、更新预览和
分阶段 GUI 状态。
